## VPS线路检测，到底在测什么

一句话：测的是你和服务器之间的那条“路”，以及这条路堵不堵。

具体拆开是三个指标：

- **Ping 值**：数据包往返一圈的时间。国内机房一般几十毫秒，日韩新加坡大概 100 多毫秒，美国和欧洲普遍 200 多毫秒。Ping 只是基准，低不等于快。
- **丢包率**：网络拥堵时，中间路由会把数据包丢掉一部分。丢包率一旦超过 5%，基本可以判定这台机器没法正常用。很多人 ping 值好看但实际卡顿，问题多半出在这里。
- **路由路径**：数据包从哪条线走。这是判断线路类型的直接证据，也是商家最爱注水的地方。

去程和回程是两个方向：你访问服务器是去程，服务器返回数据是回程。因为下行数据量远大于上行，回程线路对实际体验影响更大，检测重心应该放在回程上。有些商家只优化去程，回程走的还是普通线路，光看去程测试根本发现不了。

## 认线路：路由结果里的 IP 段都代表什么

跑完路由测试，结果里会出现一串 IP。不需要背 IP 库，认几个关键特征就能判断：

| 路由里看到的特征 | 对应线路 | 一般评价 |
| --- | --- | --- |
| 59.43.\*.\*，去程回程都有 | 电信 CN2 GIA | 优质线路 |
| 59.43.\*.\*，只在去程出现 | 电信 CN2 GT | 半程优化 |
| 全程只有 202.97.\*.\* | 电信 163 骨干网 | 普通线路，晚高峰容易拥堵 |
| 219.158.\*.\*（AS4837） | 联通 4837 | 普通线路 |
| 输出中标注 AS9929 | 联通 9929 精品网 | 优质线路 |
| 221.176 / 221.183 段（AS9808） | 移动 CMI | 普通线路 |

BestTrace 这类工具的输出自带 AS 编号，看到 AS9929 就是联通精品网，AS4837 就是普通联通线路。这里有一条核实商家宣传的核心口诀：**去回程都有 59.43 才算 CN2 GIA，只有去程有是 CN2 GT**。后面会讲到怎么用脚本验证它。

## 回程路由怎么测：backtrace 看结论，BestTrace 看路径

两个脚本配合用效果最好：backtrace 直接给你结论（走的哪条线、优质还是普通），BestTrace 给你完整路径，用来核实结论、分辨 GIA 和 GT。

### backtrace：一步出结果

登录 VPS 后执行：

bash
curl https://raw.githubusercontent.com/zhanghanyun/backtrace/main/install.sh -sSf | sh


它会测三网回程，目标是北京、上海、广州三地的电信、联通、移动共九个节点，直接输出线路判断。搬瓦工一台洛杉矶 CN2 GIA 机房的公开测试记录长这样：


北京电信 219.141.136.12  电信CN2 [优质线路]
北京联通 202.106.50.1    电信CN2 [优质线路]
北京移动 221.179.155.161 电信CN2 [优质线路]
上海电信 202.96.209.133  电信CN2 [优质线路]
……


真 GIA 机器，九个节点全是“电信CN2 [优质线路]”。有意思的是，同一家商家同样标着 GIA，香港机房就会出现电信节点走 CN2、联通和移动走普通线路的混合结果——所以别拿“这家商家是 GIA”当经验，要一台一台测。

这个脚本有个局限要注意：**它只能判断到“电信CN2”这一级，区分不了 CN2 GIA 和 CN2 GT**。要分辨这两个，得靠 BestTrace 的完整路径。

### BestTrace：看每一步走了哪

老教程里常见的命令是：

bash
wget -qO- git.io/autobesttrace | bash


它会自动测试 VPS 到中国电信、移动、联通和教育网四个方向的回程路由。不过 git.io 短链这几年已经停用，跑不动就换脚本在 GitHub 上的原始地址：

bash
bash <(curl -Lso- https://raw.githubusercontent.com/flyzy2005/shell/master/autoBestTrace.sh)


结果重点看两样：有没有 59.43 开头的节点，以及 202.97 出现在哪一段。以一台搬瓦工 CN2 GIA 机型的测试记录为例，广州电信的回程是这样的：

## 去程和丢包怎么测

去程测试不用登录服务器。用 itdog.cn 的路由追踪页面，输入服务器 IP 就能从国内多个节点发起 traceroute，适合买前快速看一眼去程走向；同一站点的 tcping 页面可以测 TCP 延迟——它比普通 ping 更接近真实使用情况，因为有些运营商会对 ICMP 测试“开小灶”，ping 出来很漂亮，实际建连接是另一回事。

买前想快速筛掉烂线路，ping.pe 也够用：输入 IP 后从全球多个位置持续 ping，实时显示延时和丢包率。重点只看两项：大陆节点的平均延时，以及大陆方向的丢包率。

## 晚高峰不测，等于白测

路由结构白天晚上不会变，但丢包率会。晚上 8 点到 10 点是使用高峰，线路挤不挤只有这个时段测得出来。白天跑分再漂亮，晚高峰丢包一上来，该卡还是卡。

所以合理的顺序是：拿到机器先跑 backtrace 和 BestTrace 确认线路类型，再连续几个晚高峰用 TCPing 盯丢包。高峰期丢包还能保持 0 或者接近 0，这台机器才算真过关。

## 常见问题

### 为什么 ping 值不高，用起来还是卡？

最常见的原因是丢包，其次是 ICMP 被区别对待。Ping 走 ICMP 协议，有些线路对它格外友好，测出来延迟很低，实际 TCP 连接完全另一个表现。所以要拿 TCPing 交叉验证，再盯住晚高峰的丢包率，三项都过关才算真的好。

### 怎么核实商家宣传的 CN2 GIA？

看回程路由里 59.43 是否全程出现：去程回程都有 59.43 是 GIA，只有去程有是 GT，全程只有 202.97 就是普通 163 线路。backtrace 这类脚本只能判断到“电信CN2”一级，分不出 GIA 和 GT，最终要以 BestTrace 的完整路径为准。
